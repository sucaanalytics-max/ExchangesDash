# CLAUDE.md

Exchange revenue analytics for NSE, BSE and MCX: Python pipelines on GitHub Actions write JSON that a static dashboard on Vercel reads. Remediation plan and audit findings: see the "Exchange Analytics — Audit Findings and Remediation Plan" doc (phases 0–5).

## Data flow

| Writer | Schedule | Reads | Writes |
|---|---|---|---|
| `scripts/nse_pipeline.py`, `bse_pipeline.py` | `exchange-update.yml`, 00:30 / 12:30 / 15:30 UTC Mon–Fri | NSE/BSE archive APIs (curl_cffi) | Supabase `nse_daily` / `bse_daily` (+ aggregates), `dashboard/data/{nse,bse}_{dashboard,enriched}_data.json` (copies in `data/`) and `…_data_eff.json` |
| `scripts/mcx_pipeline.py` | same workflow | **separate** Supabase project `mcx_daily_revenue`, written by the `sucaanalytics-max/mcx-vercel` repo | `dashboard/data/mcx_*` |
| `scripts/*_share_analysis.py` | after each daily job | yfinance, screener.in fallback | `dashboard/data/*_share_analysis.json`: price vs the previous session's revenue MA, fitted by `scripts/share_regression.py` |
| `scripts/*_live_poller.py` + `live_common.py` | `*-live.yml`, dispatched every 5 min by an external cron via `dashboard/api/trigger-live-polls.js`; no-op outside Mon–Fri 08:55–16:30 IST | NSE/BSE live turnover, yfinance quote | `dashboard/data/*_live.json`, `*_live_hourly.json`, `*_hourly_history.json` (committed to `main`); each NSE/BSE sample also to Supabase `live_samples` (`live_samples_schema.sql`) when the repository variable `ENABLE_LIVE_SAMPLES` is `true` |
| `scripts/excel_sync.py` | after daily jobs | Supabase | OneDrive Excel (append-only) |

Dashboard: `dashboard/index.html` + `js/*.js` (vanilla JS, Chart.js; one file per tab, see below) + `style.css`. The Revenue Predictor, Live Predictor, Regression and Valuation Model tabs are built from the shared `rx*` components (helpers in `js/00-core.js` after the chart-sizing code, `.rx` styles at the end of `style.css`); Revenue Summary keeps its own Excel-mirroring layout. Serverless: `dashboard/api/live.js` (proxies live JSON from GitHub raw, so live commits need no deploy), `revenue.js` (direct NSE/BSE scrape), `trigger-live-polls.js`. `/api/live` and `/api/revenue` are cached at Vercel's edge (`s-maxage`, set identically in `vercel.json` and the function), so the browser must not add cache-busting query parameters to `/api/*` URLs. Vercel project root is `dashboard/`, so its config is `dashboard/vercel.json`; its `ignoreCommand` (`vercel-ignore-build.sh`) skips builds for live-only commits and for the daily bots' data commits, so the day's data goes live with the empty `[deploy]` commit that `exchange-update.yml` pushes after the 15:30 UTC run and after every manual run (any commit whose message contains `[deploy]` builds).

## Business rules

- Indian FY runs Apr–Mar; labels look like `Q3 FY 2027` (Oct–Dec 2026). Sort quarters with `quarter_sort_key` (Python) / `quarterSortKey` (JS), never by label text.
- Every fee rate lives only in `scripts/fee_register.py`: effective-dated rules (₹/Cr per side; revenue = 2 × rate × turnover; futures on notional, options on premium, cash on traded value; IPFT excluded), each with a basis (`flat`, `slab_estimate`, `calibrated`, `calibrated_provisional`) and source (circular or results filing). `scripts/take_rates.py` derives today's statutory constants from it; `dashboard/api/revenue.js` keeps a JS copy checked by `scripts/check_take_rates.py`, which also validates the register. BSE cash is under-billed by the statutory 375 (special-rate scrip groups pay more), so the date-effective variant uses per-quarter rates calibrated to BSE's reported cash transaction income: when BSE reports a quarter, add its row to `BSE_CASH_CALIBRATED_QUARTERS` and recompute `BSE_CASH_PROVISIONAL_RATE`.
- NSE/BSE JSON comes in two variants. `{nse,bse}_{dashboard,enriched}_data.json` price every day at today's statutory rates (the same rows Supabase holds). `…_data_eff.json` re-price each day at the rules then in force (the default dashboard view): same schema plus `fee_basis` / `fee_basis_by_product` on each daily row and quarterly/monthly/weekly period, and top-level `fee_mode: "date_effective"` and `fee_rules`. Slab-era periods (NSE to 2024-09-30, BSE options 2023-11-01–2024-09-30) are flat estimates and must be labelled as such.
- NSE's quarterly P&L comes from the hand-kept Supabase table `nse_pnl`, which neither pipeline writes. Reported quarters live in `scripts/nse_reported_pnl.py` (consolidated results filings, in `nse_pnl`'s columns) and replace that table's row for the same quarter, so add each quarter on results day; `tests/test_nse_reported_pnl.py` checks that every row adds up. The default NSE forecast (`nse_ratio_model`) uses the last two reported quarters.
- MCX rows before 2024-09-02 are modelled (`mcx_historical_backfill`, `is_actual = false`: scaled to reported quarters, derived options split). They carry `modelled: true` (`modelled_days` per period) and must stay out of YoY, segment-mix comparisons and regressions. MCX `total_rev` is fut + opt; `total_rev_cr` is never used (it adds ₹0.95 Cr/day of non-transaction revenue to modelled rows).
- Muhurat and DR-test sessions are listed in `scripts/trading_calendar.py` (add each new one when the exchange announces it). The pipelines move them from `daily_all` into `special_sessions`, so they stay out of every average, day count and weekday figure; the NSE/BSE shadow-mode fallback merges them back before rebuilding. Full weekend sessions (Budget days) are normal trading days.
- Live samples are keyed on the exchange's trade date, never the wall clock; EOD is 16:00 IST (SEBI closing auction).
- Expiry weekday changed over time (NSE Thu→Tue from 2025-09-01; BSE Fri→Tue from 2025-01-06, Tue→Thu from 2025-09-01); the monthly expiry is the month's last such weekday. The effective-dated rules live only in `scripts/expiry_calendar.py` (used by `live_common.classify_day`); `dashboard/js/10-revenue-summary.js` keeps a JS copy, `EXPIRY_RULES`, checked by `scripts/check_expiry_calendar.py`. A holiday on the scheduled day moves expiry to the previous trading day (handled by the callers, from observed trading dates).
- Timestamps written by pollers are UTC with a `Z` suffix.
- Share-price regressions (`scripts/share_regression.py`; `computeShareModel` in `dashboard/js/13-regression.js` mirrors it for the DMA/lag toggles) pair each close with the revenue MA up to the previous session, computed over every revenue day. They report Newey-West t (bandwidth 1.3·√n), Durbin-Watson and an 80/20 chronological holdout against a "price unchanged" forecast. A fair value (`price_pred`) is published only with n ≥ 60, a positive slope with t ≥ 2 and a revenue MA that moved ≥ 10 %; otherwise it is null and the UI says why. R² is in-sample only.
- Supabase writes from this repo are off unless the repository variable `ENABLE_SUPABASE_WRITES` is `true` (Excel sync: `ENABLE_EXCEL_SYNC`). Keep both off while the old repo `Research-Tusk/nse-cloud-pipeline` still writes the same tables; `scripts/compare_parallel_run.py` checks parity. At cutover: run `supabase_cutover.sql`, then set `PIPELINE_SOURCE` (tags every NSE/BSE row written, column `pipeline_source`). Excel uploads use If-Match, so a workbook edited during a sync is re-synced from that version, never overwritten. BSE days whose cash file has not posted are held back for up to 7 days; days stored with cash or F&O missing are re-fetched and corrected (`bse_pipeline.corrections`).

## Working here efficiently

- Do not read `dashboard/data/*.json` or `data/*.json` whole (up to ~850 KB each; `.claude/settings.json` denies Read on the generated ones, leaving the hand-edited `bse_analyst_targets.json` and `bse_revenue_seed.csv` readable). Query them: `python3 -I -c "import json; d=json.load(open('dashboard/data/nse_dashboard_data.json')); print(d.keys())"`.
- Dashboard JS is one file per tab in `dashboard/js/` (2–55 KB each): `00-core` (state, helpers used by several tabs such as `escHtml`, `fmtChartDate`, `kpi` and the fee-basis / modelled flags, chart colours, `rx*` components, navigation, exchange switcher), `01-data` (data loading, fee mode), `02-banner-glance` (revenue banner, phone glance view), `10-revenue-summary`, `11-market-share`, `12-revenue-predictor`, `13-regression`, `14-valuation`, `15-live-predictor`, `20-reports`, `99-init`. Open the tab's file. General-purpose helpers (formatting, flags, tiles) belong in `00-core`; domain pieces stay with their tab and other tabs reuse them from there (the regression maths and `SHARE_EXCHANGE_NAMES` in `13-regression`, `SHARES_OUTSTANDING_CR` in `14-valuation`). They are classic scripts sharing one global scope, loaded in name order by `index.html`, so a new file needs its `<script>` tag, top-level code that runs at load may only use what earlier files declare, and no top-level name may be declared twice; `tests/test_dashboard_js.py` checks all three by loading the files in order. If any script fails to load, `99-init.js` shows a Reload overlay instead of starting a half-loaded page.
- Most commits are bot data updates. For human history: `git log --invert-grep --grep='📡' --grep='📈' --grep='📊'`.
- Results day (a reported NSE/BSE quarter, a new Muhurat or DR session): follow the `results-day` skill (`.claude/skills/results-day/SKILL.md`).
- Never edit committed live/data JSON by hand on a branch: bots rewrite those files on `main` every few minutes. Fix the generating code instead.

## Verify before pushing

- `python3 -m unittest discover -s tests` (tiny fixtures; also checks the dashboard JS mirrors in Node)
- `python3 scripts/check_take_rates.py`
- `python3 scripts/check_expiry_calendar.py`
- `python3 -m pyflakes scripts/<changed>.py`
- `for f in dashboard/js/*.js; do node -e "new (require('vm').Script)(require('fs').readFileSync('$f','utf8'))" || echo "$f"; done`
- UI changes: serve `dashboard/` with `python3 -m http.server` and check in Playwright (Chromium at `/opt/pw-browsers`) at 1440 and 390 px; `/api/*` must be stubbed locally.
