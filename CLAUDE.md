# CLAUDE.md

Exchange revenue analytics for NSE, BSE and MCX: Python pipelines on GitHub Actions write JSON that a static dashboard on Vercel reads. Remediation plan and audit findings: see the "Exchange Analytics — Audit Findings and Remediation Plan" doc (phases 0–5).

## Data flow

Dashboard: `dashboard/index.html` + `js/*.js` (vanilla JS, Chart.js; one file per tab, see below) + `style.css`. An **Exchanges | Brokers | MTF** switch (hidden until a view registers; each mode's button until that mode has a view) swaps the exchange pill for that mode's pill. Views register with `registerModeView(mode, view)` (VIEW MODES in `00-core.js`; `VIEW_MODES` lists each mode's key prefix, tab-id prefix and pill) and are shown through `switchExchange` under the key `<prefix><id>`; `modeOf` / `isViewKey` tell a view key from an exchange, and the `body.mode-<mode>` class hides the banner, reports and glance view. Broker views (`js/30-*.js`, built in `abiyani-tools/brokersdashboard` and merged here by PR) call `registerBrokerView` (keys `broker:<id>`); rules for Brokers PRs: `docs/BROKERS_INTEGRATION.md`. The MTF views (`js/40-mtf.js`, keys `mtf:combined|nse|bse`) read `data/mtf_daily.json`, `mtf_stocks_latest.json` and `mtf_brokers.json`: a Summary tab in the brokers' Summary layout (`mtfSummary`: average book per FY, selected quarter and month with QoQ / YoY / MoM / vs the last 125 days, last 5 / 20 / 45 days, each weekday vs its last 3 and 10; in NSE+BSE also BSE's share of the combined book, `mtfDrawShare`, as on the MTF Book tab), book and KPIs, Indian FY quarter / month averages, NSE and BSE monthly flows, top securities, and in NSE+BSE a Brokers tab (`mtfBuildBrokers`: league table of each broker's latest MTF book and market share with its moves, share over time, share by quarter end, and each broker's source); `MTF_NOTES` holds the dated notes on the exchanges' own series (BSE's level changes on 12 Mar 2024 and 1 Oct 2025, the doubled 20 Oct 2025 file, NSE's 7 % step on 1 Oct 2025 when brokers moved to gross reporting), shown on charts and marking (†) changes measured across them; every exchange's notes apply to NSE+BSE. The Revenue Predictor, Live Predictor, Regression and Valuation Model tabs are built from the shared `rx*` components (helpers in `js/00-core.js` after the chart-sizing code, `.rx` styles at the end of `style.css`); Revenue Summary keeps its own Excel-mirroring layout; its "Last 5 Days" row (and the market-share panel's) shows on hover the five sessions behind it, tagged expiry / pre-expiry, and the latest Mon–Fri with their average (the "Mon–Fri Avg (Latest)" row), with an amber chip such as `2× Wed` when a holiday made a weekday repeat in the window (`lastFiveBreakdown` in `10-revenue-summary.js`; the phone glance card shows that average as a row); beside its segment sub-tabs, live NSE and BSE cards (`buildLiveCards` in `10-revenue-summary.js`) show revenue booked, predicted close and typical-path range from `liveCardModel` in `15-live-predictor.js`, the Live Predictor's own figures. The top revenue banner shows the cards' reading (`bannerReadingFromCard`), refreshed with them from one fetch, and reads `/api/revenue` directly only while an exchange's poll feed is delayed or down. Live figures (cards, banner, Live Predictor) are compared with the actual close and QTD average at today's rates (`todayRatesData`), the polls' basis (the whole dashboard is at today's rates; there is no fee toggle). Serverless: `dashboard/api/live.js` (proxies live JSON from GitHub raw, so live commits need no deploy), `revenue.js` (direct NSE/BSE scrape), `trigger-live-polls.js`, `trigger-scheduled.js` (the daily update and mirror slots; its `SLOTS`, the `crons` in `vercel.json` and the workflows' own `schedule:` must match, as `tests/test_trigger_scheduled.py` checks). `/api/live` and `/api/revenue` are cached at Vercel's edge (`s-maxage`, set identically in `vercel.json` and the function), so the browser must not add cache-busting query parameters to `/api/*` URLs. Vercel project root is `dashboard/`, so its config is `dashboard/vercel.json`; its `ignoreCommand` (`vercel-ignore-build.sh`) skips builds for live-only commits and for the daily bots' data commits, so the day's data goes live with the empty `[deploy]` commit that `exchange-update.yml` pushes after the 15:30 UTC run and after every manual run (any commit whose message contains `[deploy]` builds).

## Business rules

- Indian FY runs Apr–Mar; labels look like `Q3 FY 2027` (Oct–Dec 2026). Sort quarters with `quarter_sort_key` (Python) / `quarterSortKey` (JS), never by label text.
- Every fee rate lives only in `scripts/fee_register.py`: effective-dated rules (₹/Cr per side; revenue = 2 × rate × turnover; futures on notional, options on premium, cash on traded value; IPFT excluded), each with a basis (`flat`, `slab_estimate`, `calibrated`, `calibrated_provisional`) and source (circular or results filing). `scripts/take_rates.py` derives today's statutory constants from it; `dashboard/api/revenue.js` keeps a JS copy checked by `scripts/check_take_rates.py`, which also validates the register. BSE cash is under-billed by the statutory 375 (special-rate scrip groups pay more), so the date-effective variant uses per-quarter rates calibrated to BSE's reported cash transaction income: when BSE reports a quarter, add its row to `BSE_CASH_CALIBRATED_QUARTERS` and recompute `BSE_CASH_PROVISIONAL_RATE`.
- NSE/BSE JSON comes in two variants. `{nse,bse}_{dashboard,enriched}_data.json` price every day at today's statutory rates (the same rows Supabase holds). The dashboard reads only the first pair (every figure at today's rates; the Fees toggle and "as charged" view were removed). `…_data_eff.json` re-price each day at the rules then in force and are still written, but nothing in the dashboard loads them: same schema plus `fee_basis` / `fee_basis_by_product` on each daily row and quarterly/monthly/weekly period, and top-level `fee_mode: "date_effective"` and `fee_rules`. Slab-era periods (NSE to 2024-09-30, BSE options 2023-11-01–2024-09-30) are flat estimates and must be labelled as such.
- NSE's quarterly P&L comes from the hand-kept Supabase table `nse_pnl`, which neither pipeline writes. Reported quarters live in `scripts/nse_reported_pnl.py` (consolidated results filings, in `nse_pnl`'s columns) and replace that table's row for the same quarter, so add each quarter on results day; `tests/test_nse_reported_pnl.py` checks that every row adds up. The default NSE forecast (`nse_ratio_model`) uses the last two reported quarters.
- MCX rows before 2024-09-02 are modelled (`mcx_historical_backfill`, `is_actual = false`: scaled to reported quarters, derived options split). They carry `modelled: true` (`modelled_days` per period) and must stay out of YoY, segment-mix comparisons and regressions. MCX `total_rev` is fut + opt; `total_rev_cr` is never used (it adds ₹0.95 Cr/day of non-transaction revenue to modelled rows).
- Muhurat and DR-test sessions are listed in `scripts/trading_calendar.py` (add each new one when the exchange announces it). The pipelines move them from `daily_all` into `special_sessions`, so they stay out of every average, day count and weekday figure; the NSE/BSE shadow-mode fallback merges them back before rebuilding. Full weekend sessions (Budget days) are normal trading days.
- Live samples are keyed on the exchange's trade date, never the wall clock; EOD is 16:00 IST (SEBI closing auction).
- Expiry weekday changed over time (NSE Thu→Tue from 2025-09-01; BSE Fri→Tue from 2025-01-06, Tue→Thu from 2025-09-01); the monthly expiry is the month's last such weekday. The effective-dated rules live only in `scripts/expiry_calendar.py` (used by `live_common.classify_day`); `dashboard/js/10-revenue-summary.js` keeps a JS copy, `EXPIRY_RULES`, checked by `scripts/check_expiry_calendar.py`. A holiday on the scheduled day moves expiry to the previous trading day (handled by the callers, from observed trading dates). Per-period expiry counts (Revenue Summary, market-share panel and trend tab, reports) are derived in the dashboard from `daily_all` (`expiryDateSet` / `countExpiryDays` in `10-revenue-summary.js`, built on `computeWeekExpiryDates`); they count the benchmark weekly expiry only, so NSE and BSE can differ by one in a month or quarter.
- Activity counts ride along on daily rows (and `special_sessions`, and the `_eff` variant) for downstream users, notably Tusk's broker tracker, which reads `dashboard/data` from raw.githubusercontent.com; no revenue figure uses them, and a count NSE/MCX did not publish is `null`, never 0. NSE: `cash_trades`, `cash_securities`, `cash_quantity` (shares; NSE publishes lakh shares) and `if/sf/io/so_contracts`; stored rows lacking them are filled from a re-fetch of their months (`fill_detail_fields`), which never touches turnover or revenue. MCX: `total_contracts`, summed from `mcx_commodity_daily`. BSE stores days whose cash is still missing after the 7-day hold-back with cash 0; `merge_cash_into_stored` completes them from their month's cash re-fetch, however old (the F&O fetch only covers 45 days).
- A stored NSE cash turnover that NSE's own files show to be wrong is fixed through `NSE_CASH_CORRECTIONS` in `scripts/nse_pipeline.py` (confirmed figure, the known-wrong value it replaces, and the source: Market Activity report `MA<DDMMYY>.csv` plus CM bhavcopy), since shadow mode never rewrites stored rows. `fill_detail_fields` prints `NOTE: … differs from NSE's …` when it sees a mismatch.
- Timestamps written by pollers are UTC with a `Z` suffix.
- MTF (`scripts/mtf_pipeline.py`): rows are keyed on the reporting date (the trading day the book is for), not the publication date. NSE republishes a date a few days later with late member submissions, in a two-block file whose right-hand (revised) block is used; each run re-reads the last 10 trading days for that and backfills older days back to 1 Apr 2021 (`HISTORY_START`, FY 2022; 40 a run, 600 on a manual run), and an older day the exchange does not serve goes under `unavailable` (retried only on a manual run; the MTF Book notes sum up the days before an exchange's first file in one line). Trading days come from the NSE/BSE dashboard JSON, and before it starts (2023-04-03) from `trading_calendar.equity_days_pre_fy24()` (weekdays less `PRE_FY24_HOLIDAYS`, plus the Muhurat days; all 324 of codex's NSE MTF dates from 23 Nov 2021 are in it). BSE's archive serves days from at least 5 Apr 2021. BSE's margin trading CSV serves days from 2025-10-01; earlier BSE days come from its margin archive (`DownloadMarginArch_ng`), whose files for later days have no rows. On 2025-10-01, the one day both serve, the archive has 3 more securities and ₹31.7 Cr (1 %) more, and it shows the same −33 % drop from 2025-09-30, so that step is BSE's own. A BSE row whose identifier is not an ISIN / security code is a totals row (kept as `published_total_cr`, never counted; BSE's archive files end with one). BSE's own 2025-10-20 file doubles the book (re-read with the totals-row fix, it still does), so that day carries the `spike` flag. When a parser fix changes stored figures, bump `PARSER_VERSION` for that exchange and its older rows are re-read. Flags are advisory except `spike` (a one-day move ≥ 25 % that reverts; left out of `combined`) and partial files (under half the usual number of securities; moved to `unavailable`); a file served for more than one date (same sha256) also goes under `unavailable` for each of them, since BSE's files carry no date (BSE served one file for 2026-01-14 and 2026-01-16). A BSE re-read that lists fewer securities than the stored day keeps the stored copy (`smaller_bse_reread`): BSE serves smaller files for older days (its 23 and 24 Sep 2026 files had 1,860 and 1,868 securities when published, 1,857 and 1,865 when asked again on 4 Nov), so the backfilled CSV-era days run slightly low and new days keep the copy read first; a parser upgrade still replaces. BSE's `arithmetic` flag is relative (opening + fresh − liquidated vs closing beyond 0.5 % of the book; its archive misses by up to 0.4 % on ordinary days) and `amount_vs_closing` marks amount financed ≠ closing by over 1 % (2024-07-01); both are recomputed on stored days every run. `mtf-sources.yml` (read-only; on demand and on PRs touching the pipeline) runs `mtf_pipeline.py --compare-bse` to put BSE's CSV and archive side by side for given dates. `public.codex_nse_mtf_daily` / `codex_public_nse_mtf_daily` (NSE totals, read by the brokers dashboard) are written by an external "codex" GitHub Actions job (`nse-mtf-daily` in `codex_pipeline_runs`) whose repository is not this one; leave them alone. The `mtf` schema's other tables (per-broker books in `mtf.broker_mtf_history` / `broker_mtf_entities`, sector views) were a one-off load in Sep 2026 of mtf.trading's files; they seeded the broker register (below) and are not read by anything here.
- Brokers' MTF books (`scripts/broker_mtf_register.py` → `mtf_brokers.json`): no exchange publishes broker-wise books since NSE's member-wise "Client Funding" report ended in Apr 2021, so each figure comes from the broker's or its parent's own document (`url`, `page`, `quote`; never mtf.trading or a news site), checked in the filing before it goes in; `BROKERS[id]["sources"]` names each broker's best recurring source. A broker's market share is its figure ÷ the NSE+BSE combined book on the same date (the last reporting date on or before a period end, within 7 days; the month's average for Angel One's monthly averages); brokers' own shares use other denominators. Each figure carries a `measure`: `share` (ICICI Bank and Kotak Bank publish their broking arms' share, not a book; the book is derived), `gross` (the exchanges' basis), `net` (net of client cash collateral or the balance-sheet loan line, 80–87 % of gross), `client_funding` (Angel One: MTF + interest-bearing receivables) or `unstated`; changes and share moves compare figures of the same measure and basis only. Basis `live` is a figure the broker keeps updating on a web page (`LIVE_FEEDS`, read on each MTF run into `mtf_broker_live.json`, never typed into `DISCLOSURES`), so its daily readings form their own series beside the filings'. Bajaj Broking's book is the BFSL overview slide's "MTF: ₹X crore" (branch + retail), not the branch slide alone. Add figures with the `broker-mtf` skill (`.claude/skills/broker-mtf/SKILL.md`).
- Share-price regressions (`scripts/share_regression.py`; `computeShareModel` in `dashboard/js/13-regression.js` mirrors it for the DMA/lag toggles) pair each close with the revenue MA up to the previous session, computed over every revenue day. They report Newey-West t (bandwidth 1.3·√n), Durbin-Watson and an 80/20 chronological holdout against a "price unchanged" forecast. A fair value (`price_pred`) is published only with n ≥ 60, a positive slope with t ≥ 2 and a revenue MA that moved ≥ 10 %; otherwise it is null and the UI says why. R² is in-sample only.
- Supabase writes from this repo are off unless the repository variable `ENABLE_SUPABASE_WRITES` is `true` (Excel sync: `ENABLE_EXCEL_SYNC`). Keep both off while the old repo `Research-Tusk/nse-cloud-pipeline` still writes the same tables; `scripts/compare_parallel_run.py` checks parity. At cutover: run `supabase_cutover.sql` (it also adds the NSE activity columns, without which upserts fail), then set `ENABLE_SUPABASE_WRITES` / `PIPELINE_SOURCE` (tags every NSE/BSE row written, column `pipeline_source`). Excel uploads use If-Match, so a workbook edited during a sync is re-synced from that version, never overwritten. BSE days whose cash file has not posted are held back for up to 7 days; days stored with cash or F&O missing are re-fetched and corrected (`bse_pipeline.corrections`).

## Working here efficiently

- Do not read `dashboard/data/*.json` or `data/*.json` whole (up to ~850 KB each; `.claude/settings.json` denies Read on the generated ones, leaving the hand-edited `bse_analyst_targets.json` and `bse_revenue_seed.csv` readable). Query them: `python3 -I -c "import json; d=json.load(open('dashboard/data/nse_dashboard_data.json')); print(d.keys())"`.
- Dashboard JS is one file per tab in `dashboard/js/` (2–55 KB each): `00-core` (state, helpers used by several tabs such as `escHtml`, `fmtChartDate`, `kpi` and the fee-basis / modelled flags, chart colours, `rx*` components, navigation, exchange switcher), `01-data` (data loading, fee mode), `02-banner-glance` (revenue banner, phone glance view), `10-revenue-summary`, `11-market-share`, `12-revenue-predictor`, `13-regression`, `14-valuation`, `15-live-predictor`, `16-contracts-premium` (NSE + BSE option contracts per ₹ Cr of premium, the same tab under every NSE/BSE view), `20-reports`, `30-brokers` / `31-brokers-price` / `32-brokers-fo-drivers` / `33-brokers-pat` / `34-brokers-valuation` (Brokers mode), `40-mtf` (MTF mode), `99-init`. Open the tab's file. General-purpose helpers (formatting, flags, tiles) belong in `00-core`; domain pieces stay with their tab and other tabs reuse them from there (the regression maths and `SHARE_EXCHANGE_NAMES` in `13-regression`, `SHARES_OUTSTANDING_CR` in `14-valuation`). They are classic scripts sharing one global scope, loaded in name order by `index.html`, so a new file needs its `<script>` tag, top-level code that runs at load may only use what earlier files declare, and no top-level name may be declared twice; `tests/test_dashboard_js.py` checks all three by loading the files in order. If any script fails to load, `99-init.js` shows a Reload overlay instead of starting a half-loaded page.
- Most commits are bot data updates. For human history: `git log --invert-grep --grep='📡' --grep='📈' --grep='📊'`.
- Results day (a reported NSE/BSE quarter, a new Muhurat or DR session): follow the `results-day` skill (`.claude/skills/results-day/SKILL.md`); a broker's new MTF figure: the `broker-mtf` skill.
- Never edit committed live/data JSON by hand on a branch: bots rewrite those files on `main` every few minutes. Fix the generating code instead.
